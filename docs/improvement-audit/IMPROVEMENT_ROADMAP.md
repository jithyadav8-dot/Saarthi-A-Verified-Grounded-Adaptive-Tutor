# Improvement roadmap

Use the score to order work within its priority class. Score = impact × evidence confidence ÷ (effort × regression risk). All four inputs use 1–5. Impact ranges from cosmetic to protecting core learner/evidence integrity. Confidence ranges from a hypothesis to a reproduced defect. Effort ranges from a local edit to a cross-system migration or study. Risk ranges from an additive change to one affecting existing identities, data or pedagogical policy. These are engineering judgments. The scores do not measure learning gain.

## Benefits, operating cost and acceptance gates

| Work | Limitation and relevant reference decision | Proposed behavior and benefit | Latency / memory / provider cost | Regression risk and validation |
|---|---|---|---|---|
| Attempts, readiness and observation | A replay changed mastery and planning unlocked prerequisites. Pramana retains assessment evidence and separates diagnostic selection. | Persist issuance and feedback together, then choose from observed readiness. A learner sees progress tied to an actual response. | Local SQLite write per issuance/grading, indexed rows grow with attempts, zero hosted calls. | Rejects stale unissued submissions and returns shorter quizzes. Check replay, rollback, concurrent retries, diagnostic posterior and multiple cycles. |
| Claim and session evidence | A real unit ID admitted an altered number. Pramana's excerpt UI illustrates the value of showing the passage. | Keep exact text spans, verification mode and score meaning with answers. A learner can inspect the relevant words after reopening chat. | Local checks proportional to evidence length, small metadata per claim, optional configured verifier adds a call. | Literal checks can reject useful derivations. Test contradictory statements, missing verdicts, partial evidence and session reload. |
| Slides | Native parser discarded tables and equations. Pramana handles native objects before selective visual processing. | Feed native table/math/notes text into the existing source unit. Search can retrieve content previously absent. | Local XML traversal, one fixture 15.50 → 16.90 ms, zero hosted calls. | Linear math can lose layout. Check slide locators, symbol ordering, existing text and source retrieval. |
| Evaluation and build | Equal requested practice masked unequal actual exposure. Remote fonts prevented an offline build. | Report counts and paired uncertainty, ship reproducible workloads and use local fonts. Easier to reproduce what a learner sees. | 2,000 bootstrap replicates on demand, small per-student arrays, zero hosted calls. | Small samples and seed sensitivity. Verify deterministic runs, unequal exposure, production build and UI. |
| Course bank | Current upload changes chat only. Pramana generates and verifies course-scoped questions. | Version questions by course/source hash, record quote, concept, key, blind verifier identity and numeric check. Resolve source deletion explicitly. Learners practice the material they supplied. | Precompute outside the request path. Store item/evidence records. Generation plus verification can cost two or more calls per candidate. | Incorrect keys, duplicate items and stale quotes. Pilot with expert-reviewed material and frozen distractor/duplicate labels before enabling automatic publication. |
| Independent evaluation | Both systems use author-influenced fixtures. Pramana includes counterfactual contexts. | Split courses at source level, freeze prompts and thresholds, blind annotators to system, score contradictions, silence and correct location separately. | Offline annotation and storage, capped optional judge calls, no student-path latency. | Label inconsistency. Report inter-rater agreement, adjudication, denominators and per-course uncertainty. |
| Deployment boundary | Both services use caller-provided learner IDs. Pramana separates course databases. | Authenticate ownership, version documents and atomically publish a course index. Isolate media jobs and enforce resource budgets. Protect history and make interrupted work recoverable. | Extra database checks, storage generations and bounded worker memory. Local jobs need no provider by default. | Highest migration risk. Test ownership denials, restart recovery and collisions before external use. |
| Selective vision | Successful ASR can miss a board-only formula. Pramana associates frames with passages. | Detect sparse/visually complex pages or board changes, preserve synchronized transcript/frame evidence, cache by content and model. | Decode/render plus optional vision per selected page/frame. Cap input pixels, concurrency and calls. | OCR can invert signs or units. Compare native-only, selective and full processing on identical licensed material with expert transcriptions. |
| Personalized remediation | One wrong answer cannot distinguish a slip from a misconception. Pramana uses item signatures, scheduling and a grounded storyboard. | Record repeated tagged errors, show possible explanations, offer a cited worked example and an unseen follow-up. Estimate time decay only after longitudinal calibration. | Small local counters and text retrieval first. Model/narration/rendering increases latency, memory and cost. | Misdiagnosis and reinforcing wrong graph edges. Test against labeled histories and measure delayed transfer before video investment. |
| Retrieval and replay | Local development workload is small and location-heavy. Pramana uses query understanding and response replay. | Experiment with rewriting, prerequisite context, parent chunks, compression and routing on frozen queries. Key caches by actual model/prompt/source version and respect retention. | Rewriting adds inference, longer contexts add tokens, vector indexes add RAM. Measure cold/warm p95 and cost per supported answer. | Query drift and stale or sensitive cache contents. Adopt only on replicated gains over current hybrid at a stated cost. |
